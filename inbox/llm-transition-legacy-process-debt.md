# Treat the LLM transition as legacy-process debt

**Status:** Candidate

## Current wording

The shift from pre-LLM workflows to LLM-native workflows creates a form of legacy-process debt.

Old systems were built under expensive assumptions:
- context had to be reconstructed manually;
- documents were slow to draft;
- state tracking was human;
- coordination depended on memory;
- repeated clarification was normal;
- every exception consumed attention.

Once LLMs, persistent context, agents, searchable history, and automation make these operations cheap, the old process stops being neutral. It becomes debt.

The right response is not to optimize every old workflow in place. It is to identify which costs belonged to the old technological regime and redesign the interface around the new one.

# 中文

## 目前表述

從非 LLM 工作流轉向 LLM 原生工作流，會產生一種「舊流程債務」。

舊系統建立在高成本假設上：
- 上下文要靠人重新拼；
- 文件產出很慢；
- 狀態追蹤靠人工；
- 協調依賴記憶；
- 反覆澄清是常態；
- 每個例外都會直接吃掉注意力。

當 LLM、持久上下文、Agent、可搜尋歷史與自動化把這些操作成本壓低後，舊流程就不再只是「舊」，而會變成債務。

因此不應只是原地優化舊流程，而要辨識哪些成本只屬於舊技術時代，並按新的技術條件重做接口。
