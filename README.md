# 100 Rules in the LLM Era

This repository is not a finished list of 100 rules.

It is a growing collection of rules discovered through real life, work, technology, AI collaboration, mistakes, experiments, and observation.

The rules are not written in advance.

They are discovered.

---

## Why this repository exists

Large language models changed more than the way we search for information.

They changed how quickly one person can:

- test an idea
- learn a new field
- compare different explanations
- build tools
- review decisions
- turn experience into reusable knowledge

But better tools do not automatically create better judgment.

In fact, faster reasoning can also make bad assumptions spread faster.

So this repository is an attempt to record a different kind of knowledge:

**small rules that survive contact with reality.**

Some rules may come from AI.

Some may come from work.

Some may come from dealing with institutions, people, money, risk, learning, or everyday life.

The source does not matter as much as one question:

> Does this rule remain useful after reality tests it?

---

## How the rules are written

We do not begin with a taxonomy.

We do not decide in advance that there must be:

- 20 AI rules
- 20 career rules
- 20 money rules
- 20 life rules
- 20 relationship rules

Instead:

**observation first, structure later.**

When something happens and a reusable principle appears, we write it down.

When enough rules accumulate, patterns and categories can emerge naturally.

The structure should grow from the rules.

The rules should not be forced into the structure.

---

## A rule is not a slogan

A useful rule should ideally contain four things:

### Rule

The shortest version of the idea.

### Observation

What happened that made the rule worth recording?

### Use

When is this rule useful?

### Failure condition

When should this rule not be applied?

Not every early rule needs all four sections.

Early drafts are allowed to remain incomplete.

---

## Status

Rules may have different levels of maturity:

- `Draft` — an observation that may become a rule
- `Working` — useful, but still being tested
- `Stable` — repeatedly useful across different situations
- `Revised` — an older rule changed after new evidence
- `Retired` — a rule that no longer survives reality

A rule being written here does not mean it is permanently true.

Revision is part of the project.

---

## The basic principle

The goal is not to reach 100 as quickly as possible.

The goal is to eventually have 100 rules worth keeping.

So the repository may grow slowly.

A new rule should exist because something real made it necessary.

Not because the list needs another number.

---

## Working method

The project follows a simple sequence:

**Observe → Discuss → Draft → Test → Revise → Keep**

LLMs can help with:

- finding alternative explanations
- researching evidence
- compressing observations
- identifying hidden assumptions
- challenging a rule
- improving wording

But the final rule remains a human judgment.

AI is part of the process.

It is not the authority.

---

## Current state

This project started in October 2026.

There is no predetermined final structure yet.

That is intentional.

We will write the rules first.

Then we will see what kind of book they become.

# LLM 時代的 100 條規則

這個 repository 不是一份已經完成的 100 條規則清單。

它是一個持續成長的規則集合。

這些規則來自真實生活、工作、科技、AI 協作、錯誤、實驗與觀察。

這些規則不會事先寫好。

它們是被發現的。

---

## 為什麼要建立這個 repository

大型語言模型改變的，不只是我們搜尋資訊的方式。

它也改變了一個人完成很多事情的速度，例如：

- 測試一個想法
- 學習一個新的領域
- 比較不同的解釋
- 建立工具
- 檢查自己的決策
- 把經驗轉換成可以重複使用的知識

但工具變得更強，不代表判斷一定會變得更好。

事實上，更快的推理速度，也可能讓錯誤的假設傳播得更快。

所以這個 repository 想記錄的是另一種知識：

**那些真正和現實碰撞之後，依然能留下來的小規則。**

有些規則可能來自 AI。

有些可能來自工作。

有些可能來自和制度、人、金錢、風險、學習，或者日常生活打交道的經驗。

規則來自哪裡沒有那麼重要。

更重要的是一個問題：

> 當現實真正測試它之後，這條規則還有沒有用？

---

## 這些規則怎麼寫

我們不會先建立一套分類。

也不會一開始就決定一定要有：

- 20 條 AI 規則
- 20 條職涯規則
- 20 條金錢規則
- 20 條生活規則
- 20 條人際關係規則

而是：

**先有觀察，之後才有結構。**

當一件事情發生，而且其中出現了一個可以重複使用的原則，我們就把它寫下來。

等累積到足夠多的規則之後，再看看它們自然形成了哪些模式與分類。

結構應該從規則裡長出來。

而不是先有結構，再把規則硬塞進去。

---

## 一條規則不是一句口號

一條真正有用的規則，理想上應該包含四個部分：

### 規則

這個想法最短的版本。

### 觀察

發生了什麼，讓這條規則值得被記下來？

### 適用情境

什麼時候這條規則有用？

### 失效條件

什麼情況下不應該套用這條規則？

不是每一條早期規則都一定要立刻具備完整的四個部分。

早期草稿可以保持不完整。

---

## 狀態

不同規則可以有不同的成熟程度：

- `Draft` — 一個可能成為規則的觀察
- `Working` — 已經有用，但仍然在測試
- `Stable` — 在不同情境中反覆證明有用
- `Revised` — 因為新的證據而被修改過
- `Retired` — 已經無法繼續通過現實檢驗的規則

一條規則被寫進這裡，不代表它永遠正確。

修改，本來就是這個專案的一部分。

---

## 最基本的原則

目標不是盡快湊到 100 條。

目標是最終留下 **100 條真正值得保留的規則**。

所以這個 repository 可能會長得很慢。

一條新的規則應該出現，是因為現實中真的發生了某件事，讓它有存在的必要。

而不是因為清單剛好缺下一個編號。

---

## 工作方式

這個專案遵循一個很簡單的流程：

**觀察 → 討論 → 草擬 → 測試 → 修改 → 保留**

LLM 可以協助：

- 找出其他可能的解釋
- 搜尋與驗證證據
- 壓縮觀察
- 找出隱藏的假設
- 挑戰一條規則
- 改善文字表達

但一條規則最終是否成立，仍然是一個人的判斷。

AI 是整個過程的一部分。

但它不是最終權威。

---

## 目前狀態

這個專案開始於 2026 年 10 月。

目前沒有預先設定好的最終結構。

這是刻意的。

我們會先把規則寫出來。

然後再看看，它最後會長成一本什麼樣的書。
